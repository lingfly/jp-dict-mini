## 1. 问题（Why）

**现在发生了什么？**

`utils/fsrs/fsrs.js:28-40` 把调度器参数写死在 `getScheduler()` 里：

```js
fsrs({
  enable_fuzz: true,
  enable_short_term: true,
  request_retention: 0.9,
  maximum_interval: 36500,
  learning_steps: ['1m', '10m'],
  relearning_steps: ['10m']
})
```

全仓库只有这一处创建调度器，页面层无法覆盖，用户更无法调整。想改任何一项都必须改代码 + 发版。

**谁受影响？** 所有复习用户。FSRS 默认参数是通用折中；备考用户需要更高保持率、更短间隔，长期学习者需要更低复习量。一套参数必然有一边不满意。

**为什么必须存后端？** 调度在客户端计算，但参数代表"这个人的复习策略"。只存本机会让同一账号在两台设备上算出不同间隔，清缓存/重装后偏好丢失。

**为什么默认值保持 36500（界面「不限」）？** 默认值等于现状，存量用户行为零变化。想让长间隔收敛的用户，可以主动选 30/90/180/365/730 天；默认不替用户做"收紧"的决定。

## 2. FSRS 参数清单（事实整理）

> 依据：`utils/fsrs/index.js`（ts-fsrs v5.4.1，`FSRSVersion = "v5.4.1 using FSRS-6.0"`）。

### 2.1 ts-fsrs 调度参数（`generatorParameters` 认识的 7 项）

| 参数 | 类型 / 取值 | 库默认 | 代码现值 | 作用 | 本次处理 |
|------|-------------|--------|-----------|------|----------|
| `request_retention` | number，`(0, 1]` | `0.9` | `0.9` | 目标记忆保持率。通过 `intervalModifier = (r^(1/decay) - 1) / factor` 缩放长期间隔；**值越高，同一稳定度下间隔越短、复习越频繁**（`decay` 取 `w[20]`，FSRS-6 默认 0.1542） | ✅ 开放（档位） |
| `maximum_interval` | number，天，`1–36500` | `36500` | `36500` | 长期间隔的硬上限，同时约束 fuzz 区间上界（`next_interval` 会 `Math.min`） | ✅ 开放（档位）；默认保持 36500（界面「不限」） |
| `enable_fuzz` | boolean | `false` | `true` | 对 ≥2.5 天的间隔做随机抖动（2.5–7 天 ±15%，7–20 天 ±10%，>20 天 ±5%），避免同批卡片总在同一天堆积 | ❌ 不开放，固定 `true` |
| `w` | number[21]，17/19/21 长度会被迁移补齐；每项受 `CLAMP_PARAMETERS` 约束 | `default_w`（FSRS-6 官方权重） | 同默认 | 记忆模型权重：初始稳定度、难度、遗忘曲线形状。换 `w` 等于换一套算法 | ❌ 不开放 |
| `enable_short_term` | boolean | `true` | `true` | 是否启用 Learning/Relearning 步骤；关闭后新卡直接进 Review（≥1 天） | ❌ 不开放，固定 `true` |
| `learning_steps` | string[]，单位 `m`/`h`/`d` | `['1m','10m']` | 同默认 | 新卡学习步长。**本项目额外做了一层换算**：步长分钟数 = 当天队列中"再过 N 张卡"（`calcCardOffset`，`1 分钟 = 1 卡片`） | ❌ 不开放 |
| `relearning_steps` | string[]，单位 `m`/`h`/`d` | `['10m']` | 同默认 | 遗忘（Again）后的重学步长，语义同上 | ❌ 不开放 |

**参数生效的边界**（写在库实现里，改之前必须知道）：

- `w` 与 `request_retention` 共同决定间隔；改 `request_retention` 不动 `w`，只缩放倍数。
- 学习步长 `>= 1440` 分钟时，库直接把卡片置为 `Review` 并按天排期；`1–1439` 分钟则 `scheduled_days = 0`，进入本项目的"当天回插"分支。
- 所有参数只影响**下一次及以后**的计算，不回溯修改已存的 `due` / `stability` / `difficulty`。
- 参数非法（如 `request_retention <= 0`、`maximum_interval <= 0`）会在 `getScheduler()` 时抛 `FSRSValidationError`；没有兜底会导致整个复习页打不开。

### 2.2 项目自有的调度常量（不是 ts-fsrs 参数，但同样决定"下次什么时候出现"）

| 项 | 位置 | 现值 | 说明 | 本次是否动 |
|----|------|------|------|-----------|
| 评分映射 | `fsrs.js` `RATING_MAP` | `0/1/2/3 → Again/Hard/Good/Easy` | 四级评分对应关系 | 否 |
| 分钟 → 卡片偏移 | `fsrs.js` `calcCardOffset` | `1 分钟 = 1 卡片`，最少 1 | 短间隔卡的队列插入位置 | 否（也是步长不开放的原因） |
| 当天毕业判定 | `review-list.js:433-434` | 仅 `Review && scheduled_days > 0` 算毕业 | 其余按偏移回插队列 | 否 |
| 响应时间上限 | `reviewTimer.js` | `60000ms` | #003 口径，不参与调度 | 否 |
| 版本契约 | `dataSource.js` `FSRS_VERSION` | `'5.4.1'` | 随提交上报，必须与库版本一致；**不随参数变化** | 否 |
| 每日新词数量 | `/api/user/learning-config/dailyNewWords` | 用户可配 | 控制学习量，不是 FSRS 参数 | 否 |

### 2.3 不开放其余参数的原因

| 参数 | 不开放的理由 |
|------|-------------|
| `enable_fuzz` | 固定 `true`，作用是打散同日堆积，属"分布微调"而非复习强度；用户难以感知。范围已定为只两项。 |
| `w`（21 个权重） | 只能由 FSRS 优化器基于大量复习日志拟合；手填无意义，且不同长度会被自动迁移、超界会被 clamp，用户看到的数值与实际生效值不一致。 |
| `enable_short_term` | 关闭会跳过 Learning/Relearning，导致现有"当天短间隔回插"整段失效、四级评分预览全部变成"≥1 天"。固定 `true`。 |
| `learning_steps` / `relearning_steps` | 与"1 分钟 = 1 卡片"耦合：用户选「10m」期望 10 分钟后，实际是"再过 10 张卡"；当天队列只有 3 张时会变成 1 分钟后。**先解决"按真实时间重排"再开放**，否则是给用户一个说谎的旋钮。 |

## 3. 目标（What）

> 一句话：把"目标保持率"和"最大间隔"做成设置页可调项，参数存后端、跨设备一致；默认值 `0.90 / 36500 天（不限）`，只影响之后的调度，不重排已有卡片。

- 本次**不做**：开放 `enable_fuzz`、`w`、`enable_short_term`、`learning_steps` / `relearning_steps`。
- 本次**不做**：重排（reschedule）已有卡片。已存的 `due` 不动，参数只作用于下一次评分。
- 本次**不做**：按词单/分组设置不同参数；不做"参数生效时间/历史"。
- 本次**不做**：修改 `/api/fsrs/*` 任何接口字段、请求体、`fsrsVersion`；参数不进复习请求体，后端也不得用参数重算调度。
- 本次**不做**：新增页面或复习页入口；设置页除新增「复习参数」区块与给现有四项加「通用设置」标题外，不改动现有设置项。
- 本次**不做**：实现后端代码。本仓库负责前端 + 契约文档（`backend-api.md`），后端按文档实现并**先上线**。
- 本次**不做**：修改 `pages/learn`（无入口的遗留页面）。
- 明确**不改**的既有行为：响应时间口径（#003）、3001 静默跳过、提交失败停留当前卡、队列回插规则。

## 5. 用户与场景

| 角色 | 场景 | 现在怎么做 | 期望怎么做 |
|------|------|-----------|-----------|
| 备考用户 | 两个月后考试，想把记住的比例提上去 | 没有入口，只能多刷 | 保持率调到 95%，同一张卡的间隔明显变短 |
| 长期学习者 | 不想每天被大量复习压住 | 没有入口 | 保持率降到 85%，复习量下降 |
| 想控制长间隔的用户 | 卡片一次比一次排得远 | 无法控制 | 可选 30/90/180/365/730 天封顶（默认「不限」） |
| 多设备用户 | 手机上调过参数，平板继续复习 | 无参数可调 | 平板进入复习页即用同一组参数 |
| 保守用户 | 试了参数觉得不合适 | — | 一键恢复默认（0.90 / 不限） |

## 6. 方案

### 6.1 存储与接口契约

沿用现有 `learning-config` 模式（每项配置一个 PUT 子路径，参见 `ai-dict-config`）。完整字段、校验、SQL、示例与测试用例见同目录 **`backend-api.md`**。

| 方向 | 接口 | 变化 |
|------|------|------|
| 读 | `GET /api/user/learning-config` | 响应新增 `fsrsRequestRetention`（number）、`fsrsMaximumInterval`（number，天）。正常**始终返回且不为 `null`**；后端列默认 `0.900` / `36500` |
| 写 | `PUT /api/user/learning-config/fsrs-config` | **部分更新**：请求体只含本次修改的字段，至少一项；两项同时提交且任一非法则整次拒绝（业务码 `2005`） |

关键约定：

- 后端只做**存储 + 范围校验**，不参与调度计算（卡片状态仍由前端算好后提交），不做额外数据回填（历史行由 DDL 列默认值填充）。
- 后端 v2 起两列为 `NOT NULL DEFAULT 0.900/36500`，接口不再返回 `null`。**默认值有两处载体（DDL + 前端常量），必须同值**；调整默认值需同时改两处。
- 错误码 `2005` 表示参数不合法；前端判据是 `code != 200`，提示由 `utils/request.js` 统一给出一次，页面只负责回滚。
- 旧版小程序忽略新增字段；新版前端在旧后端上表现为"显示默认值、保存失败（提示由请求层给出）"。
- **后端已于 2026-10-26 按 v3 上线；前端按 v3 实现后发版。**

### 6.2 前端读取时序

```text
复习页 onLoad
  → await getApp().waitForLogin()            // C-05，避免 401 二次登录
  → 参数来源优先级：
      ① 本次运行内设置页刚保存的值（内存）
      ② 服务端 GET /api/user/learning-config  ← 常规路径
      ③ 本机缓存（上次成功获取的值，仅请求失败时兜底）
      ④ 默认值（0.90 / 36500）                ← 兜底，允许继续答题
  → 应用参数后，计算评分预览与调度
```

- 复习页已有一次 `getLearningConfig()`（用于释义折叠），本次把"参数"并入同一次请求，不新增往返。
- 请求失败且有缓存：用缓存；**无缓存：用默认值继续答题，不弹提示**（卡片列表请求失败会由现有错误态处理）。
- 设置页保存成功后更新内存值；复习页下一次展示卡片即生效，无需重启。

### 6.3 界面：分组与参数项

设置页分组（现有四项**仅加标题**，行为与样式不变）：

| 分组 | 内容 |
|------|------|
| 通用设置 | 每日新词数量、单词发音、查询时释义折叠、复习时释义折叠（现有四项） |
| 复习参数 | 标题行右侧「恢复默认」；目标记忆保持率、最大复习间隔、生效说明 |
| 管理员配置 | 现状不变（仅管理员可见） |

| 界面项 | 参数 | 形态 | 取值 | 默认 |
|--------|------|------|------|------|
| 目标记忆保持率 | `request_retention` | 选择器（复用设置页现有 picker 模态） | 80% / 85% / 90% / 95%（带"轻松/较轻松/标准/牢固"） | 90%（标准） |
| 最大复习间隔 | `maximum_interval` | 选择器 | 30 天 / 90 天 / 180 天 / **365 天** / **730 天（两年）** / 不限 | 不限（`36500`） |

## 7. 成功标准

| 类型 | 标准 | 怎么观测 |
|------|------|----------|
| 功能 | 保持率 90% → 95% 后，同一张 Review 卡的预览间隔变短（如「6天后」→「4天后」） | 复习页评分按钮下方文案对比 |
| 功能 | 最大间隔设为 30 天后，评分预览不再出现「>30 天」；设为 730 天后可出现「730天后」 | 构造高稳定度卡片，看预览 |
| 功能 | 默认「不限」：长稳定度卡片预览可超过 365 天（如「800天后」） | 默认账号复习长间隔卡 |
| 功能 | 手机改参数后，平板重新进入复习页即使用同一参数 | 两台设备对比预览与 Network |
| 功能 | 修改后无需重启小程序即生效；重启后仍保留 | 设置 → 复习 → 杀进程重开 |
| 接口 | 保存只提交本次修改的一项；业务码 `2005` 时界面回滚且只有一条提示 | Network 面板看请求体；构造 `2005` |
| 接口 | 默认值两处同值：新账号 GET 返回 `0.9 / 36500`，设置页显示「90% / 不限」 | 新账号 GET + 设置页 |
| 体验 | 设置页顶部显示「通用设置」；「复习参数」标题右侧显示「恢复默认」；现有四项行为不变 | 手动过一遍 |
| 功能 | 已有卡片的 `due` 不被改写 | 修改前后 `GET /api/fsrs/due` 对比同一 `wordId` |

| 健壮 | 配置请求失败且无缓存时，用默认值正常进入答题 | 断网/改响应包 |
| 健壮 | 参数缺失/非法/请求失败时不出现 `FSRSValidationError`、复习页可打开 | 改响应包 |

## 8. 风险与未知

| 风险 / 未知 | 影响 | 处理方式 |
|-------------|------|----------|
| 默认「不限」使长稳定度卡仍可能排到数年后 | 用户觉得"这个词再也不会出现" | 属现状行为；提供 30/90/180/365/730 档供主动收紧 |
| 默认值双载体漂移（DDL `0.900/36500` vs 前端常量） | 未设置用户在不同版本前端看到不同参数 | 验收时核对两处同值；改默认值需同时改 DDL 与常量；契约以 `backend-api.md` v3 为准 |
| 后端契约后续变更（部分更新 / `2005` 语义） | 前端按旧契约实现会多写字段或误判错误 | `backend-api.md` 为唯一契约，变更需同步前端并复核本 spec |
| 配置请求失败且无缓存 → 用默认值 | 若用户实际设了 0.85/730，本次会用 0.90/36500 计算并提交，产生一次与偏好不一致的排期 | 用户已确认接受；只在网络异常时发生，不阻塞答题 |
| 复习页首屏多依赖一次配置请求 | 首屏变慢 | 与已有 `getLearningConfig` 合并；与 `due` 并行请求，取到后渲染首卡 |
| 参数未就绪就被用于计算（并发未 await） | 首次预览/评分用默认值 | 实现时用"应用后才算"的单一路径，并在 `design.md` 写清时序 |
| 用户把最大间隔从「不限」改小，期望老卡片立刻提前 | 误以为没生效 | 区块底部说明「只影响之后的复习安排，已排好的到期日不变」 |
| 保持率调到 95% 后复习量明显上升 | 误以为出 bug | 选项文案标注「越高记得越牢，复习越频繁」 |
| 登录冷启动与配置请求抢跑 | 401 触发二次登录 | 先 `await waitForLogin()`（C-05） |
| 后端字段被手工改成档位外的合法值（如 0.87） | UI 无法显示 | 前端白名单校验 → 回落默认；下次保存写回档位值 |

**待确认问题**：无（2026-10-26 用户已确认范围、存储、默认值、档位、恢复默认、失败口径）。剩余仅为"是否批准实施"。
