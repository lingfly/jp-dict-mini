# 规格增量：FSRS 参数可配置（保持率 / 最大间隔，参数存后端）

> 本文件是增量：只描述本次新增/修改的行为，归档时合并进 `specs/capabilities/review-scheduling/spec.md`。
> 范围与取值按用户确认（2026-10-26）：只开放 `request_retention`、`maximum_interval`，参数存后端；默认 `0.90 / 36500 天（不限）`；失败且无缓存时用默认值。
> 本改动新增 `learning-config` 字段与 PUT 接口，属数据契约变更（L3）；后端实施依据见同目录 `backend-api.md`。

## 新增需求

### R1 参数来源与生效

- **AC-01** 当小程序冷启动直接进入复习页时，系统应先用 `await getApp().waitForLogin()` 等待静默登录完成，再请求学习配置，避免 401 触发重复登录。
- **AC-02** 当系统计算评分预览（`getRatingPreviews`）或下次复习（`scheduleNext`）时，应使用当前生效参数；取值优先级为：① 本次运行内设置页保存成功的值 → ② 服务端 `GET /api/user/learning-config` → ③ 本机缓存（仅当 ② 失败） → ④ 默认值（`0.90` / `36500`，与后端列默认值同值）。
- **AC-03** 当服务端返回 `fsrsRequestRetention` / `fsrsMaximumInterval` 时，系统应使用服务端值计算，并把该值写入本机缓存；缓存只用于"请求失败时兜底"，不得在服务端可用时覆盖服务端值。
- **AC-04** 当参数请求失败且本机无缓存时，系统应使用默认值（`0.90` / `36500`）继续答题，不得阻塞复习流程，也不得弹出与参数相关的提示（卡片列表请求失败仍按既有错误态处理）。
- **AC-05** 当用户在设置页保存参数成功后，本次运行内下一次展示卡片（含切换卡片、重新进入复习页）即应使用新值；小程序重启后应从服务端重新读取并继续生效。
- **AC-06** 当参数发生变化时，系统不得修改任何已存在卡片的 `due` / `stability` / `difficulty` / `state`，也不得触发全量重排或批量写后端。

> AC-06 的验收口径：参数修改前后各调用一次 `GET /api/fsrs/due`，同一 `wordId` 的 `due` 值不变。

### R2 设置界面

- **AC-07** 设置页应分为「通用设置」「复习参数」「管理员配置」三个分组并显示分组标题。「通用设置」包含现有四项：每日新词数量、单词发音、查询时释义折叠、复习时释义折叠（行为与样式不变，仅新增标题）；「复习参数」位于「通用设置」之后、管理员配置之前（普通用户看不到管理员区块时位于页面末尾），其**标题行右侧为「恢复默认」**，区块内依次为目标记忆保持率、最大复习间隔、生效说明。
- **AC-08** 目标记忆保持率应为选择器，显示当前值的百分比；可选项为 `80%（轻松）`、`85%（较轻松）`、`90%（标准）`、`95%（牢固）`，默认 `90%（标准）`。
- **AC-09** 最大复习间隔应为选择器，显示当前值；可选项为 `30 天`、`90 天`、`180 天`、`365 天`、`730 天（两年）`、`不限`，默认 `不限`（`36500` 天）。
- **AC-10** 当用户在任一选择器中点「确定」且保存成功时，系统应关闭选择器、更新显示值，并提示「已更新」；请求体**只包含本次修改的那一项**，不得带 `null` 或未修改字段（后端为部分更新）。
- **AC-11** 当保存失败（业务码非 200，如 `2005`；或网络失败）时，系统应把界面回滚到保存前的值；错误提示由 `utils/request.js` 统一给出一次，页面不得重复提示（保持"错误只有一个出口"）。
- **AC-12** 当用户点击「恢复默认」并在确认弹窗中点「恢复」时，系统应**显式提交两项**默认值（`0.90` / `36500`，即使某项已是默认值），成功后提示「已恢复默认」；取消则不做任何变更。

#### 场景

```gherkin
场景：设置页分组
  假设 用户进入设置页
  那么 顶部显示「通用设置」标题，其下是每日新词数量、单词发音、查询时释义折叠、复习时释义折叠
  并且 紧接着显示「复习参数」标题，标题同一行右侧是「恢复默认」

场景：把保持率从 90% 调到 95%
  假设 设置页当前显示「90%（标准）」
  当   用户选择「95%（牢固）」并点「确定」
  那么 设置页显示「95%」并出现 toast「已更新」
  并且 进入复习页后，高稳定度卡片的「N天后」预览比调整前更短

场景：最大间隔设为 30 天
  假设 某卡片稳定度对应的下次间隔为 120 天
  当   用户把最大复习间隔设为「30 天」
  那么 该卡片的评分预览最多显示「30天后」

场景：两年档
  假设 某卡片稳定度对应的下次间隔为 500 天
  当   用户把最大复习间隔设为「730 天（两年）」
  那么 该卡片的评分预览显示「500天后」（不被截断）

场景：默认不限
  假设 用户从未改过参数
  当   某卡片稳定度对应的下次间隔为 800 天
  那么 评分预览显示「800天后」

场景：跨设备
  假设 用户在手机把保持率改为 95%
  当   用户在平板重新进入复习页
  那么 平板使用 95% 计算预览与调度

场景：只影响之后
  假设 卡片 A 的 due 是 45 天后
  当   用户把最大间隔改为「30 天」
  那么 卡片 A 的 due 仍为 45 天后；只有卡片 A 下次评分后的新 due 受 30 天限制

场景：参数取不到
  假设 用户本机无参数缓存
  当   配置请求失败
  那么 复习页用默认值 0.90 / 36500 正常出卡、可评分，不弹参数相关提示
```

### R3 边界与兼容

- **AC-13** 当服务端返回的参数缺失、为 `null`、类型错误或不在允许集合内时（正常 v3 后端不会返回 `null`，此条覆盖旧后端与异常数据），系统应按字段回落到默认值，不得抛出 `FSRSValidationError`，不得阻止设置页其余配置项与复习页加载。
- **AC-14** 当后端尚未提供新字段时（旧版本后端），系统应使用默认值、不报错；当保存接口不可用（404/网络失败）时，按 AC-11 回滚界面，提示由请求层给出。
- **AC-15** 参数变化不得改变以下既有行为：四级评分按钮的数量与映射、`responseTimeMs` 口径、3001 静默跳过、提交失败停留当前卡、队列回插规则、`fsrsVersion = '5.4.1'`。

#### 异常场景

| 场景 | 预期行为 |
|------|----------|
| 未登录冷启动直接进复习页 | 先等待静默登录，再拉配置与卡片；不出现"刚打开就弹错误" |
| 冷启动直接进设置页 | 沿用现有 `getLearningConfig()`；失败时区块显示默认值，不阻塞页面（与现有配置项一致） |
| 旧后端缺字段、或异常返回 `null` / 类型错误 | 两项按默认值显示与计算；不提示、不报错（v3 正常不会返回 `null`） |
| 服务端返回越界值（如保持率 `1.5`、间隔 `0`） | 对应项回落默认；其余合法项照常生效 |
| 服务端返回合法但不在档位内（如 `0.87`、`45`） | 视为非法，按默认值处理（白名单策略，下一次保存会写回档位值） |
| 参数请求失败、本机缓存存在 | 使用缓存值继续答题，不提示 |
| 参数请求失败、无缓存 | 使用默认值继续答题（AC-04），不提示 | 
| 保存失败（业务码 `2005` / 网络 / 接口不存在） | 界面回滚；错误提示由请求层给出一次（AC-11），页面不重复弹 |
| 保存成功但返回 `data` 为完整配置对象 | 前端可忽略 `data`，按本次提交值更新显示（AC-10） |
| 复习过程中在设置页改了参数 | 已展示卡片的预览不重算；下一张卡或重新进入复习页后使用新值 |
| 参数被改成"更严格"（保持率↑、间隔↓） | 已排期卡片不提前；只影响后续评分，属预期行为 |
| 旧版小程序读新后端 | 忽略新增字段，行为不变 |

## 接口契约（增量）

| 接口 | 字段 | 类型 | 约束 | 缺省 |
|------|------|------|------|------|
| `GET /api/user/learning-config` | `fsrsRequestRetention` | number | 正常**始终返回且非 `null`**；前端档位集合 `0.80/0.85/0.90/0.95`，后端只校验范围 `0 < x <= 1`、最多 3 位小数 | 后端列默认 `0.900`；前端兜底 `0.90` |
| 同上 | `fsrsMaximumInterval` | number（天） | 正常始终返回且非 `null`；前端档位集合 `30/90/180/365/730/36500`，后端只校验范围 `1–36500` | 后端列默认 `36500`；前端兜底 `36500` |
| `PUT /api/user/learning-config/fsrs-config` | 仅本次修改的字段 | — | **部分更新**：至少提交一项；两项同时提交且任一非法 → 整次拒绝（业务码 `2005`）；不得传 `null` | 成功 `{ code: 200, data: <完整配置> }`（前端可忽略 `data`） |

> `36500` 即界面上的「不限」。「恢复默认」需显式提交两项。后端只存储与校验，不参与调度计算。
> 默认值有两处载体：后端列默认（DDL）与前端常量，必须同值；调整默认值需同时改两处。

## 已知限制（归档时写入能力规范）

- 默认最大间隔保持 `36500`（界面「不限」）：长稳定度卡片仍可能被排到数年后；想控制上限的用户可主动选「30/90/180/365/730 天」。
- 参数请求失败且本机无缓存时用默认值计算，可能在网络异常时产生一次与用户偏好不一致的排期（用户已确认接受）。
- 参数不参与 `due-forecast` 计算（该接口统计的是已存 `due`），改参数不会重算历史预测。
- 默认值有两处载体（后端 DDL `0.900`/`36500`、前端常量 `0.90`/`36500`），调整时必须同时改，否则不同版本前端对"未设置用户"的表现会不一致。
- 学习/重学步长仍固定在代码里（`1m / 10m / 10m`），改步长需先解决"分钟 → 卡片数"的近似（另开需求）。
- 不提供"修改前/后对比"或参数变更历史；设置页只展示当前值。
