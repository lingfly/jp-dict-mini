## 界面契约

> 凡是涉及界面的 AC，必须在这张表里写清"长什么样、在哪、点了之后怎么样"。
> **检验**：另一个人只看这张表，能画出一样的界面吗？画不出，就是没写清。
>
> 实现后不符合预期，九成是这张表缺了某一列。

| AC | 出现位置 | 形态 | 文案（逐字） | 用户动作 | 消失条件 |
|----|---------|------|-------------|---------|---------|
| AC-01 | | 提示条 / 按钮 / 弹窗 / 图标 / **不新增元素** | | | |

**四条硬要求**

1. **位置**：页面哪个区域、哪个元素的上面/下面/替换掉谁。
2. **形态**：提示条、按钮、弹窗、图标——**或者明确写"不新增元素"**。
3. **文案**：逐字写出来。不要写"类似…的提示"，那是给实现者自由发挥的空间。
4. **动作**：用户点哪里、触发什么。如果复用已有按钮，写出按钮上的字。

**"不加东西"也必须写**

很多返工来自"要不要加"。设计上就是复用已有入口时，必须写死：

| 场景 | 形态 |
|------|------|
| 搜索失败 | **不新增元素**，靠 toast + 用户再点「查询」 |
| 列表加载失败 | 列表区替换为提示块，用户下拉刷新 |

## EARS 句式速查

| 类型 | 句式 | 适用 |
|------|------|------|
| 事件驱动 | 当 <事件> 时，系统应 <行为> | 点击、提交、返回 |
| 状态驱动 | 在 <状态> 期间，系统应 <行为> | 加载中、编辑态、多选态 |
| 异常处理 | 如果 <条件>，系统应 <行为> | 超时、失败、无权限 |
| 可选特性 | 当 <配置> 开启时，系统应 <行为> | 开关、灰度 |
| 普遍约束 | 系统应 <行为> | 始终成立 |

**写 AC 的四条铁律**

1. **可判断**：第三个人看完能说出"过了/没过"。
2. **一个 AC 一件事**：出现"并且"就考虑拆成两条。
3. **不写实现**：写"系统应展示剩余次数"，不写"系统应用 setData 更新 aiQueryRemain"。
4. **界面行为写到元素级**：只要 AC 涉及界面，就必须在「界面契约」里写清位置、形态、文案、动作、消失条件。**"提供重试"不是行为描述，是待办事项。**

**反例 → 正例**

| 反例 | 问题 | 正例 |
|------|------|------|
| 系统应快速响应 | 无法判断 | 系统应在 1.5 秒内展示首屏结果 |
| 系统应友好地提示错误 | 无法判断 | 系统应提示「网络异常，请重试」 |
| 系统应提示失败并提供重试按钮 | **重试在哪？按钮还是下拉？点了之后？** | 见「界面契约」：评分条上方一行提示 + 用户再点评分按钮 |
| 系统应支持开关 | 没说开关影响什么 | 当开关关闭时，系统应跳过 AI 查词，直接展示普通搜索结果 |
| 系统应处理各种异常 | 范围无边 | 如果请求超时，系统应保留上次结果并提示可重试 |
