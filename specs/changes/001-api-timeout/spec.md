# 规格增量：接口超时治理

> 只描述行为，不描述实现。归档时合并为一节「全局请求约束」。

## 新增需求

### R1 超时与错误分类

- **AC-01** 当请求超过 60 秒未返回时，系统应终止请求，并提示「请求超时，请重试」。
- **AC-02** 当设备无网络时，系统应提示「网络不可用，请检查连接」，不得与超时使用同一文案。
- **AC-03** 当服务端返回 5xx 时，系统应提示「服务繁忙，请稍后重试」，不得提示「网络错误」。

### R2 提示与加载态

- **AC-04** 当请求失败或结束时，页面 loading 应被关闭，不得停留在加载态。
- **AC-05** 当一次请求失败时，系统应只弹 1 次 toast；页面可以展示内联错误状态，但不得再弹第二个 toast。

### R3 重试策略

- **AC-06** 系统不应自动重试任何超时请求；失败后是否重试由用户决定。
- **AC-07** 当搜索、词单列表、复习提交失败时，系统应保留用户输入或当前卡片，并提供可用的重试方式（复用页面已有的查询按钮、下拉刷新，或提供明确的重试入口），使用户无需重新填写即可再次发起同一请求。其中复习提交失败时，应停留在当前卡片、保持评分按钮可用，用户再次选择评分即视为重试。

### R4 401 与重新登录

- **AC-08** 当多个请求同时返回 401 时，系统应只发起 1 次重新登录，不得并发多次。
- **AC-09** 当 401 回包到达时，如果该请求发出时携带的 token 与当前 token 不同，系统应直接用当前 token 重试，**不得清除**已刷新的登录信息。
- **AC-10** 当重新登录后的重试仍返回 401 时，系统应停止重试，并提示「登录已失效，请重新打开小程序」。
- **AC-11** 当 401 后重试请求时，系统应使用原请求的 timeout 值，不得回落到默认值。

### R5 可观测与特殊接口

- **AC-12** 当请求失败或耗时超过 5 秒时，系统应上报请求路径（不含查询参数）、耗时、timeout 值与错误类型。
- **AC-13** 当 AI 查词轮询超过 5 分钟仍未返回结果时，系统应终止轮询并提示「AI 查词超时，请稍后重试」；轮询期间应展示阶段提示（已提交 / 生成中）。
- **AC-16** 当用户在 AI 查词轮询期间切换到其他页面时，系统应继续轮询；返回首页后应展示当前状态（生成中 / 结果 / 失败），且不得在其他页面弹出与该查询相关的提示。
- **AC-17** 当单次轮询请求失败（超时或断网）时，系统不应终止整个 AI 查词流程，应在剩余总时长内继续轮询；连续失败 3 次或超过总时长才终止。

### R6 兼容

- **AC-14** 当页面未按新错误对象改造时，系统应保持原有 `reject` 行为可用，不得因新增字段导致页面报错。
- **AC-15** 当复习提交因超时失败并由用户重新选择评分时，系统应沿用首次评分时的响应时间，不得把超时等待的时长计入。

#### 场景

```gherkin
场景：请求超时
  假设 请求发出后 60 秒仍无响应
  当   用户搜索「ありがとう」
  那么 页面停止转圈，展示「请求超时，请重试」
  并且 提供「重试」按钮
  并且 只出现一个提示

场景：断网与超时要能区分
  假设 用户关闭了移动网络与 WiFi
  当   用户打开词单列表
  那么 提示「网络不可用，请检查连接」
  并且 不提示「请求超时」

场景：超时不自动重试
  假设 一次复习提交超时
  当   系统判定失败
  那么 不自动重发请求
  并且 保留当前卡片与已选评分，允许用户手动重试

场景：多个接口同时 401
  假设 首页同时发出了 3 个需要 token 的请求
  当   3 个请求都返回 401
  那么 只调用 1 次登录接口
  并且 3 个请求各自用新 token 重试 1 次
  并且 新 token 不会被后到的 401 清除

场景：重登后仍然 401
  假设 重新登录成功，但服务端仍拒绝新 token
  当   重试请求再次返回 401
  那么 系统停止重试
  并且 提示「登录已失效，请重新打开小程序」
```

## 界面契约

> 这张表是本次实现的**唯一形态依据**。实现时按行照做，不要自行增删元素。
> 检验：另一个人只看这张表，能画出一样的界面吗？

| AC | 出现位置 | 形态 | 文案（逐字） | 用户动作 | 消失条件 |
|----|---------|------|-------------|---------|---------|
| AC-05 | 全局（请求层统一弹） | toast，无图标，3 秒 | 超时「请求超时，请重试」；断网「网络不可用，请检查连接」；5xx「服务繁忙，请稍后重试」；登录失效「登录已失效，请重新打开小程序」 | 无 | 3 秒自动消失；1 秒内相同文案不重复弹 |
| AC-07 搜索 | 首页·结果区 | **不新增元素** | 仅依赖 AC-05 的 toast | 再点「查询」或键盘确认 | toast 自动消失；关键词保留在输入框 |
| AC-07 词单 | 词单页·列表区 | 浅黄提示块，替换列表区 | 首行「加载失败」，次行「下拉刷新可重试」 | 下拉刷新 | 刷新成功后 |
| AC-07 复习列表 | 复习页·列表区 | 浅黄提示块，替换列表区 | 首行「加载失败」，次行「下拉刷新可重试」 | 下拉刷新 | 刷新成功后 |
| AC-07 复习 | 复习页·评分条上方 | 固定浮层提示条（`bottom: 86px + 安全区`） | 「请求超时，请重试」 | 再点「忘记 / 模糊 / 认识 / 简单」 | 提交成功后 |
| AC-07 学习 | 学习页·评分区上方 | 内联提示条 | 「提交超时，请重新选择」 | 再点「忘记 / 模糊 / 认识」 | 提交成功后 |
| AC-07 纠错 | 纠错页·提交按钮上方 | 内联提示条 | 「请求超时，请重试」 | 再点「提交纠错」 | 提交成功后 |
| AC-13 | 首页·AI 入口文案 | 替换入口文字，不加新元素 | 「正在提交查询…」→「已提交，生成中…」 | 无 | 出结果或失败 |
| AC-16 | 首页·AI 入口下方 | 内联提示条 | 「AI 查词超时，请稍后重试」 | 再点 AI 入口 | 重新发起后 |

**实现约束**

- 搜索页**不得**出现提示条、重试按钮、错误图标。
- 复习页、学习页的提示条在评分条上方，不遮挡评分按钮。
- 所有提示条背景 `#FFF4E5`、圆角 8–10px、字号 13–14px，与现有风格一致。

## 修改需求

| 原行为 | 新行为 | 原因 |
|--------|--------|------|
| 60 秒默认值散落在 `request` 签名里，GET / PUT / formPost 无法覆盖 | 统一 60 秒，集中在常量表，三个方法支持可选覆盖 | 时长不变，但改一处即可全局生效 |
| `fail` 统一提示「网络错误」 | 按类型区分超时、断网、服务异常 | 用户需要知道下一步做什么 |
| 业务码非 200 时请求层弹 toast | 由页面决定如何展示 | 避免双重提示 |
| 每个 401 各自清 token、各自触发登录 | 并发只登一次；token 已刷新则不清、直接重试 | 避免二次登录与新 token 被误清 |
| 401 重试无次数上限、丢失 timeout | 最多 1 次，保留原 timeout | 防止死循环与超时降级 |
| 失败后无重试入口 | 三个高频页提供手动重试 | 用户不必退出重进 |

## 明确不变的行为

> 写下来，防止实现时"顺手优化"。

- 接口路径、请求参数、返回结构完全不变
- **超时时长仍为 60 秒**（本次不调短，也不分级）
- **任何超时都不自动重试**（含 GET）
- 401 无感重登的整体体验不变（用户不需要手动登录）
- AI 同步查词 300 秒上限不变
- FSRS 的 `clientRequestId` 幂等机制不变
- 不做请求取消、不做离线队列
