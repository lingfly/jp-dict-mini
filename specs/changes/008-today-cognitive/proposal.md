## 1. 问题（Why）

**现在发生了什么？** 复习页把当天卡片刷完后，只有一句 toast「今日复习完成」和一个 ✓「今日复习已完成」空态卡片（`pages/review-list/review-list.wxml` 的 `done-state`）。用户看不到"今天到底复习了多少、记得怎么样、花了多久"，完成动作没有任何正反馈；想了解只能自己切到「学习统计」页再逐日点柱子。

**谁受影响？** 每天完成复习的用户（高频、每次会话结束都会看到）。

**有多疼？** 每次复习结束都遇到，属于"完成即失忆"。

**证据**：`review-list.wxml` 完成态仅 3 行文案；后端已提供日维度接口且文档明确写了「前端接入点（完成页）」。

## 2. 目标（What）

> 一句话：让**刚复习完的用户**在完成页直接看到今天的四档认知分布、新学/复习数量与时长，从而对当天的学习有个交代，不用再跳到统计页。

## 3. 非目标（Out of Scope）★

- 本次**不做**：图里的绿色「今日复习完成」**按钮**——按用户要求只显示文字，不可点击，不新增返回首页/再刷新的入口。
- 本次**不做**：不做历史日期切换、不做曲线图；历史与趋势仍归「学习统计」页（`pages/review-forecast`）。
- 本次**不做**：不改评分按钮、tabBar 角标、响应计时、FSRS 调度、3001 静默等既有行为。
- 本次**不做**：不改 `/api/fsrs/due-forecast`（106 天主接口）的用法与统计页展示。
- 明确**不改**的既有行为：`due > 0` 且有卡时不新增任何提示，直接按现有流程（进入即拉卡出卡）继续复习。

## 4. 用户与场景

| 角色 | 场景 | 现在怎么做 | 期望怎么做 |
|------|------|-----------|-----------|
| 复习中的用户 | 刷完最后一张卡 | 一句 toast + 「今日复习已完成」 | 看到今日四档分布、新学/复习、时长 |
| 复习中的用户 | 中途离开再回来，还有卡 | 直接出卡，无中间页 | 完全不变，且不新增提示 |
| 新用户 | 今天一张卡都没有 | 「今日复习已完成」 | 不显示全 0 明细，只说明今天没复习记录 |

## 5. 成功标准

| 类型 | 标准 | 怎么观测 |
|------|------|----------|
| 功能 | 完成态且后端 `due === 0` 时展示详情卡，四行 + 三列与接口数值一致 | 真机刷完当天卡片，逐项比对接口响应 |
| 功能 | 后端 `due > 0` 且有卡时不展示详情卡，直接继续出卡；无卡时展示详情并留一条 `console.warn` | 构造两种场景（短间隔卡 / 后端口径异常） |
| 体验 | 切到复习页的完成态不再出现旧完成页，只有「加载中...」→ 详情卡 | 真机反复切 tab |
| 体验 | 进入完成态到详情卡出现 ≤ 1 秒（真机 4G） | 真机计时 |
| 降级 | 详情接口失败时详情卡照常显示、数值为「—」、条形为空，不白屏、不重复弹错，且不出现旧完成页 | 断网/改错路径试一次 |
| 降级 | `due > 0` 且无卡时详情卡照常显示，Console 有且仅有一条 `warn` | 构造该场景后看日志 |
| 口径 | 四行数值之和 = 接口 `easy+good+hard+forgot`；新学 + 复习 = `newLearned + review` | 手工核对一次 |

## 6. 风险与未知

| 风险 / 未知 | 影响 | 处理方式 |
|------------|------|----------|
| 短间隔卡（`INTRADAY_TRIGGERED`）当天会再出现，`due` 可能仍 > 0 | 用户"感觉学完了"却看不到详情卡 | 按 `due === 0` 硬判定，`> 0` 时静默继续出卡；这是后端口径，不前端篡改 |
| 跨零点：23:59 完成、00:01 渲染 | 展示成昨天/今天的数字错位 | 比对 `data.date` 与本地日期，不一致重拉一次；仍不一致按返回日期展示 |
| 时长口径刚变更（当天全部复习累计） | 与旧印象对不上 | 由后端统一，前端只展示；文案不加"估算"字样 |
| 详情接口失败 | 完成页只有旧文案 | 静默降级为现有空态，错误提示交给请求层一次 |
| 今天一张卡都没学（新用户） | 全 0 明细像故障 | 四档之和为 0 时只显示「今日暂无复习记录」 |

**待确认问题**（未勾选 = 阻塞批准；得到答案后改成 `- [x]`，并在冒号后补结论）

- [x] **待确认** 日期标题格式？→ 用户答复：「日期格式用斜杠」，即 `2026/10/28`（月、日补零）。
- [x] **待确认** 时长超过 1 小时怎么展示？→ 用户答复：「「N 小时 N 分 N 秒」一行放不下，还是改成时：分：秒展示」。结论：改冒号格式，`1:11:45`；不足 1 小时为 `17:25`；0 为 `0:00`；秒补零两位。**（此条为批准后的修订，状态已退回 draft 待重新批准）**
- [x] **待确认** `due > 0` 时的表现？→ 用户答复：「不需要显示「N 个待复习 + 开始复习」，而是和现状一样直接开始复习」，即不新增提示，直接按现有流程重新拉卡出卡。
- [x] **待确认** 切到复习页会先闪一下旧完成页，怎么处理？→ 用户答复：「这个是不需要的，去掉，due=0 或 due>0 但无卡都显示最新的详情页；但 due>0 但无卡其实属于缺陷，记录一条日志」。结论：旧完成页在完成态永久下线，取数期间显示「加载中...」，`due > 0` 且无卡时展示详情并 `console.warn` 一条缺陷日志。
- [x] **待确认** 详情接口**失败**时显示什么？→ 用户答复：「详情接口失败时样式还是这样，只是没有数据」。结论：仍用详情卡版式，数值显示「—」、条形为空，日期用本地当天，不加错误提示条/按钮。

## 8. 验收摘要

> 详细规格见 `spec.md`。

- AC-01 进入完成态时调用一次今日认知接口
- AC-02 `due > 0` → 不展示详情、不加提示，直接继续出卡
- AC-03 `due === 0` → 展示今日详情卡
- AC-04 接口失败 → 详情卡照常显示，数值为「—」，不回退旧完成页
- AC-12 取数期间只显示「加载中...」，旧完成页不再出现
- AC-13 `due > 0` 但无卡 → 展示详情，并在控制台留一条缺陷日志
- AC-06/07 四行恒显示，条长按四档之和归一
- AC-08 底部三列：新学 / 复习 / 时长
- AC-09 只显示文字「今日复习完成」，无可点元素
- AC-10 四档全 0 → 只显示「今日暂无复习记录」
- AC-11 `due > 0` 且重拉仍无卡 → 只重拉一次，转现有空闲态，不反复请求
