# 今日认知情况接口（后端 spec 007）

> 对应后端 `specs/007-today-cognitive-stats/`。**纯新增端点**，既有接口零改动，前端可随时接入。

## 1. 端点

```
GET /api/fsrs/due-forecast/today
Header: Authorization: Bearer <token>
入参：无（固定今天，服务端按本地时区切分自然日）
```

## 2. 响应结构

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "date": "2026-10-28",
    "due": 350,
    "durationSeconds": 0,
    "cognitive": { "easy": 0, "good": 0, "hard": 0, "forgot": 0 },
    "reviewAndNew": { "review": 0, "newLearned": 0 }
  }
}
```

`data` **直接是日项对象**，不是数组、不包 `days`。五个键与两个子对象恒定存在（0 也不会省略）。

## 3. 字段语义

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | string | `yyyy-MM-dd`，服务端本地时区；前端可核对是否等于「今天」，跨零点时避免误用 |
| `due` | number | 今日待学，**累计口径**（含此前逾期未处理的卡片），与 `/api/fsrs/due-count` 同口径 |
| `durationSeconds` | number | 今日学习时长（秒），当天全部复习的反应时间求和后四舍五入 |
| `cognitive.easy/good/hard/forgot` | number | 今日简单/认识/模糊/忘记，同词同日只计第一次评分；四项之和 = 今天学过的单词数 |
| `reviewAndNew.review/newLearned` | number | 今日复习/新学，同词同日只计一次，两项互斥，之和 = 今天涉及的单词数 |

## 4. 与统计主接口的关系

- 本接口返回值与 `GET /api/fsrs/due-forecast` 中 `date == 今天` 的 `days[]` 元素**逐字段相等**（同一套服务端代码计算）。
- 后端已用单测钉住这一一致性；前端不必再从 106 项里 `find` 今日项。

## 5. 前端接入点（完成页）

1. **调用时机**：当日学习完成、进入完成页时调用一次。
2. **完成判定**：`due === 0` 表示今天没有待学卡片；若还想区分「真学完了」与「今天一张卡都没学」，再加判 `easy + good + hard + forgot === 0`。
3. **不要再用主接口查今日**：统计页（曲线）用 `/due-forecast`，完成页（今日数字）用本接口，两处数值天然一致。
4. **跨零点提示**：若 `data.date` 与本地日期不一致（用户在 23:59 打开完成页、00:01 才渲染），建议重新拉取一次。

## 6. 口径变更说明（2026-10-28）

后端在验证中发现并修复了一个统计口径缺陷：**学习时长此前只统计每个单词当天第一次复习的耗时，现按当天全部复习累计**（符合 spec 006 REQ-STAT-005 的原文）。影响：

- 完成页的 `durationSeconds` 会比修复前略大（同词一天内被复习多次时）；
- 统计页历史日的时长同样按新口径返回（2026-08-15 实测从 2417 秒变为 6316 秒，与 SQL 逐日核算一致）；
- 四档、新学/复习、待学的口径与数值均无变化。
