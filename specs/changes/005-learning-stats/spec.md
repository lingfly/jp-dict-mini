## 新增需求

### R1 数据获取与解析

- **AC-01** 当用户进入学习统计页时，系统应等待静默登录完成后再请求学习统计接口，不得在未拿到 token 时发请求。
- **AC-02** 当学习统计接口返回成功时，系统应按后端返回的 `days` 顺序渲染全部数据日，不新增、不合并、不跳过任何一天。
- **AC-03** 系统应只使用新契约字段（`date` / `due` / `durationSeconds` / `cognitive.*` / `reviewAndNew.*`），不得读取或兼容任何已删除的旧字段。
- **AC-04** 如果接口返回的 `days` 缺失、为空或不是数组，系统应展示空状态「暂无学习记录」，不得展示空白图表。
- **AC-05** 如果请求失败（业务码非 200、网络错误、超时），系统应在图表区域展示失败态并提供重试入口；错误提示只由请求层给出一次，页面不得再弹第二条提示。

### R2 两个图表与切换

- **AC-06** 页面应在图表上方提供两个切换项，文案依次为「认知情况」「新学复习」。
- **AC-07** 当用户进入页面时，系统应默认选中「认知情况」。
- **AC-08** 当用户点击另一个切换项时，系统应切换为对应图表；两个图表的横轴、纵轴与柱高口径完全一致，切换不改变任何数值。
- **AC-09** 当切换图表时，系统应把选中日期重置为今天，并把横向滚动位置重置为今天居中。
- **AC-10** 两个图表应使用同一套纵轴上限，同一天在两张图中的柱总高度相同。
- **AC-11** 每个图表应展示：纵轴刻度、可横向滚动的柱体、横轴日期标注、图例。

### R3 柱体构成

- **AC-12** 「认知情况」图中的一根柱应由五段自下而上堆叠组成：简单、认识、模糊、忘记、待学；各段高度与对应数值成正比，柱总高为五段之和。
- **AC-13** 「新学复习」图中的一根柱应由三段自下而上堆叠组成：新学、复习、待学；柱总高为三段之和。
- **AC-14** 当某一段的数值为 `0` 时，系统不应绘制该段。
- **AC-15** 当某一段的数值大于 `0` 但对应高度不足 4rpx 时，系统应按 4rpx 绘制，保证可见。
- **AC-16** 当某一段的数值为 `null`（未来日的认知/新学复习块、历史日的待学）时，系统不应绘制该段，且不得按 `0` 处理。

### R4 横轴与初始位置

- **AC-17** 图表一屏应完整展示 7 天，其余日期通过横向滑动查看。
- **AC-18** 横轴标注应显示相对今天的日期文案：前天、昨天、今天、明天、后天，更早为「N天前」，更远为「N天后」。
- **AC-19** 当页面首次展示或切换图表时，系统应把横向滚动位置定位到「今天」这一列居中。

### R5 点击查看详情

- **AC-20** 当用户点击某一列（柱体或该列的日期标注）时，系统应把该列标记为选中，并在图表下方展示该日的详情卡。
- **AC-21** 详情卡应展示该日期的完整构成：日期、四档认知（简单/认识/模糊/忘记）、新学、复习、待学、学习时长。
- **AC-22** 当某个数值在该日不存在（`null`）时，详情卡对应项应显示「—」，不得显示 `0`。
- **AC-23** 当被点击的日期是未来日时，详情卡应展示日期与待学，其余项显示「—」，并展示一行说明「这一天还没到」。
- **AC-24** 详情卡的学习时长应按「N 分 N 秒」展示；不足 1 分钟展示「N 秒」；为 `0` 展示「0 秒」。

#### 场景

```gherkin
场景：查看昨天的评分构成
  假设 用户昨天评过 55 个词：简单 3、认识 42、模糊 8、忘记 2
  当   用户在学习统计页点击「昨天」那一列
  那么 图表下方出现详情卡，标题为昨天日期
  并且 详情卡显示「简单 3」「认识 42」「模糊 8」「忘记 2」
  并且 该列柱子被高亮

场景：查看未来某天
  假设 今天是 2026-10-27，用户滑到最右侧
  当   用户点击「15天后」那一列
  那么 详情卡显示该日期与「待学 N」
  并且 简单/认识/模糊/忘记/新学/复习 六项均显示「—」
  并且 详情卡出现「这一天还没到」

场景：切换图表
  假设 用户当前在「认知情况」并选中了 3 天前
  当   用户点击「新学复习」
  那么 图表切换为新学复习的堆叠柱
  并且 选中日期重置为今天，详情卡显示今天
  并且 横向滚动定位回今天居中

场景：后端契约变更导致解析失败
  假设 接口返回的 data 中没有 days
  当   用户进入页面
  那么 图表区展示「暂无学习记录」
  并且 页面不白屏、不出现未捕获异常
```

**补充约束（写入验收口径，避免实现自由发挥）**

1. 详情卡**常驻**：页面有数据时始终存在，不因点击空白处消失。
2. 详情卡初始内容是**今天**，不是空占位。
3. 两张图的图例必须与各自柱段颜色严格对应；不得共用一套图例。
4. 不新增任何页面级浮动按钮、分享入口、时间范围选择器。
5. 图例中的数字（旧版「今日简单：3」这类）取消，数字统一由详情卡承担——避免同一信息两处口径。
