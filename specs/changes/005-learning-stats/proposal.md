## 1. 问题（Why）

**现在发生了什么？**

后端 `/api/fsrs/due-forecast` 已按后端 spec 006 改成「学习统计」，是**破坏性变更**：`data` 由数组变为 `{ days: [...] }`，旧字段 `reviewCount / newLearnedCount / forgotCount / hardCount / goodCount / easyCount / dueCount` 全部删除 [backend-api.md §2、§5]。

前端现状（`pages/review-forecast/review-forecast.js`）：

- `review-forecast.js:92` 判断 `Array.isArray(res.data)`，新接口下恒为 `false` → **统计页直接空白**（不是报错，是"看起来没数据"）。
- `review-forecast.js:115-131` 全部读旧字段，即使解析通了也拿不到值。
- 时间窗口是 46 天（旧图），新接口固定 106 天（今天往前 90 天 + 今天 + 往后 15 天），横轴与柱宽都需重算。
- 一屏按 46 天排布，106 天沿用会导致每根柱约 48rpx，手指点不准具体日期。

**谁受影响？** 所有查看「学习统计」的用户（个人中心 → 学习统计卡片）。上线后不修即全员看到空白页。

**有多疼？** 100% 复现，且是**静默**的——用户不会看到错误提示，只会以为自己的学习记录丢了。

**证据**：`backend-api.md` §6「旧版客户端按数组解析会拿不到数据（`Array.isArray` 为 false），统计页会空白」。

**为什么顺带做「点柱看详情」？**

新接口每天带 7 个数字（4 档认知 + 待学 + 复习 + 新学 + 时长）。106 天 × 7 个数字，柱高只能表达"多少"，表达不了"分别是多少"。不点开具体某天，用户永远看不到自己那天到底错在哪一档。

## 2. 目标（What）

> 一句话：让**复习中的用户**能够在学习统计页用两个切换图（认知情况 / 新学复习）看到最近 90 天到未来 15 天的每日构成，并通过**点击某一天的柱子**看清那一天的四档评分、新学复习、待学与学习时长。

## 3. 非目标（Out of Scope）★

- 本次**不做**：修改后端任何字段、口径、时间窗口；`days` 一定是 106 条，前端不重算日期。
- 本次**不做**：时间范围切换（近 7 天 / 30 天 / 全部）——用户已选「一屏 7 天 + 横向滑动」，全量 106 天可滑到。
- 本次**不做**：两张图之间的日期联动——用户已明确"分别展示，不会存在联动"。
- 本次**不做**：第三个图表（「学习安排」类）——`due` 已作为堆叠柱的一段存在两张图里。
- 本次**不做**：个人中心「学习统计」卡片（已学习 / 已掌握 / 每日目标）的任何改动。
- 本次**不做**：复习完成页的统计展示（`TODO.md` 第 9 条，另开 change）。
- 本次**不做**：图表库、手势缩放、长按分享、截图导出（C-08 不引入依赖）。
- 本次**不做**：`durationSeconds` 的柱状可视化（只在详情卡里显示文字）。
- 本次**不做**：横竖屏 / 大屏适配。
- 明确**不改**的既有行为：`/api/fsrs/due-count`、`/api/fsrs/due`、提交复习、FSRS 参数（#004）、响应计时口径（#003）、请求层超时与提示（#001）。

## 4. 用户与场景

| 角色 | 场景 | 现在怎么做 | 期望怎么做 |
|------|------|-----------|-----------|
| 复习中的用户 | 想知道昨天学得怎么样 | 只能看到一根柱的总高度 | 点昨天的柱，看到「简单 3 / 认识 42 / 模糊 8 / 忘记 2 / 待学 — / 学习时长 12 分 30 秒」 |
| 复习中的用户 | 想知道自己是"忘得多"还是"模糊多" | 完全看不到 | 认知图上四档颜色分段，谁高谁矮一眼看出 |
| 复习中的用户 | 想知道新词和复习的比例 | 靠猜 | 切到「新学复习」图，看新学 vs 复习两段比例 |
| 复习中的用户 | 想知道今天还欠多少 | 要去复习页看角标 | 认知图今天的柱顶端有一段灰色待学，点开有确切数字 |
| 复习中的用户 | 想看未来会不会爆量 | 看不到 | 往右滑到未来 15 天，只有灰色待学段 |

| 类型 | 标准 | 怎么观测 |

## 6. 风险与未知

| 风险 / 未知 | 影响 | 处理方式 |
|-------------|------|----------|
| 前端不发版，后端先上 | 统计页全员空白 | 必须同版本发布（backend-api.md §6）；本次改动即修复 |
| 今日 `due` 是累计值（示例 350，含逾期），会把纵轴上限顶到很高 | 历史日的柱子显得很矮（如 55 词 → 约 1/7 屏高） | 采用**全期统一纵轴**（两张图同高，保证可比较）；数字精度由详情卡承担。若体验仍差，另开 change 处理（见 §7 决策记录） |
| 一屏 7 天 = 每根柱约 80rpx | 手指点柱仍可能点到相邻列 | 柱宽取满列宽并加选中高亮，点击目标是整列（含柱下方标签区域） |
| `null` 与 `0` 混用（后端明确两者语义不同） | 未来日被画成 0 高度、历史待学被写成 0 | AC 里逐条区分：`null` 不画/显示「—」，`0` 正常画零值 |
| 契约再次变更 | 前端解析失效 | `backend-api.md` 为唯一契约；变更需同步本 spec |
| 106 列 × 7 个数字的渲染量 | 首屏略慢 | 一次请求一次 `setData`，不逐列更新 |

**待确认问题**：无（2026-10-27 已确认：双图切换、默认认知、无联动、一屏 7 天、堆叠且 due 为其中一段、两张图都画 due、详情卡形态、切图重置今天、未来日展示口径、待学文案、学习时长展示）。
