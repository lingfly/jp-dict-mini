# #016 进入词单加词页自动聚焦搜索框 — 规格

> L1 变更，但本次改动是纯界面行为，按 AGENTS.md §4 的界面契约要求写清位置、形态、文案、动作、消失条件。

## 界面契约

| 编号 | 位置 | 形态 | 文案 | 动作 | 消失条件 |
|------|------|------|------|------|----------|
| UI-16-01 | 词单内查词页（`pages/wordlist-add-search`）顶部搜索栏 | 沿用现有原生 `<textarea class="search-input">`，**不新增任何元素**；进入页面后自动获得焦点，底部弹出系统输入法键盘，输入光标可见 | 占位符不变：`输入日语单词、句子或长文本，如：ありがとう` | 自动聚焦（无需用户点击）；聚焦后可直接输入、点「查询」或键盘「完成/搜索」 | 用户点键盘收起、点页面其它区域或离开页面 → 键盘收起；本需求不产生任何新的常驻元素 |

## 行为 AC（EARS）

- **AC-01** 当用户从词单详情页点「＋ 添加单词」进入词单内查词页时，系统应在页面转场结束、首次渲染完成后
  自动聚焦顶部搜索输入框，使系统输入法键盘直接弹出，**无需用户再点击输入框**；
  从页面出现到可输入的时间应不超过 1 秒。
- **AC-02** 当用户在某条结果的单词详情中返回查词列表（页内返回，`backToResults`）时，
  系统**不得**再次自动聚焦搜索框或重新弹出键盘。
- **AC-03** 当用户手动收起键盘（点键盘收起 / 点页面其它区域）后，系统在本页停留期间**不得**再次自动弹起键盘。
- **AC-04** 系统**不得**为本需求新增任何可见界面元素（无新按钮/提示/浮层）；
  搜索框的占位符、`maxlength=2000`、`auto-height`、`fixed`、`bindinput`/`bindconfirm`、
  「查询」按钮、最近查询、结果列表、详情、AI 查词、分组弹层与加词提交的行为**均不变**。
- **AC-05** 自动聚焦**不得**改变或阻塞 `onLoad` 既有流程：`await getApp().waitForLogin()` 登录等待、
  分组加载、学习配置加载照常执行；即使登录失败 / 分组加载失败 / 网络异常，聚焦与键盘弹出仍应发生
  （聚焦是本地行为，不依赖网络）。
- **AC-06** 本次改动**不得**引入新依赖、构建链或新页面路由（宪法 C-08 / C-07）；
  修改后的页面 JS `node --check` 通过，`node scripts/spec.js check` 无新增错误。

## 边界与异常

| 场景 | 预期行为 |
|------|----------|
| iOS 页面转场未结束就设置焦点 | 延迟到 `onReady` 之后一帧再置 `focus=true`，确保转场完成后聚焦 |
| 用户在 300ms 延迟内自己点了输入框 | 原生组件重复聚焦幂等，不产生副作用 |
| 用户在延迟窗口内退出页面 | `onUnload` 清理定时器，不得在已卸载页面执行 `setData` |
| 从详情返回列表 | 不重新聚焦（AC-02），键盘保持用户当前状态 |
| 登录未完成 / 接口失败 | 照常聚焦（AC-05），不因网络阻塞输入 |

## 数据契约

无新增/修改接口、无新增字段；本变更仅涉及页面内 UI 状态（`searchAutoFocus`）。
