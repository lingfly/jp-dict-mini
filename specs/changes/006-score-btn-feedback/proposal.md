## 1. 问题（Why）

**现在发生了什么？**

1. **评分没有手感**：复习页底部四个评分按钮（忘记 / 模糊 / 认识 / 简单）目前只有 WXSS 的 `:active` 提供按下反馈（alpha 0.12 → 0.22 + `scale(0.96)`）。真机上 `:active` 在部分机型延迟甚至不触发，小程序里更可靠的是 `hover-class`。结果是点完评分后除了卡片切换没有任何"我确实按到了"的确认，误触只能靠看卡片变化判断。
2. **一个死页面还挂在路由表里**：`pages/learn/learn` 仍在 `app.json` 的 `pages` 中注册，页面走的是早已废弃的旧复习接口（`/api/review/next-word`、`/api/review/submit`，评分为 0/1/2 三档），**全仓库没有任何入口能进入它**（tabBar 的「复习」指向 `pages/review-list/review-list`，无任何 `navigateTo` 指向 learn）。它同时是 `reviewApi.getNextWord` / `submitReview` 两个新旧混合封装的唯一调用方，所以这两个封装也一直删不掉。

**谁受影响？** ① 所有做每日复习的用户（高频、单手操作）；② 维护者（`api.js` 里留着一组只为死页面存在的封装，`app.json` 声明着不存在的业务流程）。

**有多疼？** ① 每张卡都点一次，一天几十到上百次；② 低频但持续误导：读代码的人会以为"学习页"是现行流程。

**证据**：`grep -r "pages/learn" --include=*.{js,json,wxml,wxss}` 仅命中 `app.json:10` 与 learn 自身文件；`reviewApi.` 的全部调用点为 `learn.js:56 / learn.js:143`（另两条 `getLearningStatus` 在 `profile.js:64`、`wordlist-detail.js:111`）。

## 2. 目标（What）

> 一句话：让**复习中的用户**在按下评分按钮（以及点空白处看答案）时立刻得到**触感确认**、评分按钮另有**颜色加深**；同时**把零入口的旧学习页及其专属接口封装从仓库里清掉**，让路由表与 `api.js` 只反映现行流程。

## 3. 非目标（Out of Scope）★

- 本次**不做**：不新增"震动反馈"设置开关，不扩 `learning-config` 接口。
- 本次**不做**：不改四个评分按钮的文案、排序、配色基调、下次复习时间预览，不改任何评分/调度逻辑。
- 本次**不做**：不删 `reviewApi.getLearningStatus`（「我的」与「词单详情」仍在用）。
- 本次**不做**：不动后端 `/api/review/*` 接口本身，也不动 `utils/request.js`。
- 本次**不做**：不清理 `#002` 之外的其它死代码（例如 `pages/new-word-audit` 的越权直连写法）。
- 本次**不做**：空白区（「点击空白处显示答案」）只加触感，**不加**底色变化或缩放缓动。
- 明确**不改**的既有行为：提交中重复点击只提交一次（AC-RS-07）、提交失败停留当前卡片（AC-RS-11）、`responseTimeMs` 口径（AC-RS-15 ~ AC-RS-19）。

## 4. 用户与场景

| 角色 | 场景 | 现在怎么做 | 期望怎么做 |
|------|------|-----------|-----------|
| 复习中的用户 | 看到答案后点「认识」 | 底色变化不明显/有延迟 | 按下瞬间底色变深，同时手机轻震一下 |
| 复习中的用户 | 提交中误触第二次 | 无反馈差别 | 视觉仍加深，但不会多提交、不会多震 |
| 维护者 | 读 `app.json` / `api.js` | 看到不存在的学习流程与只为它存在的封装 | 只剩现行流程与在用接口 |

## 5. 成功标准

| 类型 | 标准 | 怎么观测 |
|------|------|----------|
| 功能 | 四个按钮按下期间底色明显深于常态（alpha 0.12 → 0.40），且不糊成纯色块 | 开发者工具 + 真机逐一点击 |
| 功能 | 每次按下触发一次 light 级震动，抬起后不重复触发 | 真机手感 + `vibrateShort` 调用计数 |
| 功能 | 点空白处显示答案时同样有一次轻震，区域本身不变色 | 真机点空白区 |
| 体验 | 按下到变色的延迟 ≤ 100ms | 真机观察（`hover-start-time="0"`） |
| 降级 | 不支持震动的设备照常可评分，无报错 | 开发者工具（无震动）下点一遍 |
| 结构 | `app.json` 页面数 25 → 24，`pages/learn/` 不再存在 | 编译无报错，全仓库无 `pages/learn` 引用 |
| 结构 | `utils/api.js` 方法数 67 → 65，仅剩 `getLearningStatus` 一个 `reviewApi` 方法 | 重跑引用扫描，`reviewApi` 未引用数为 0 |

## 6. 风险与未知

| 风险 / 未知 | 影响 | 处理方式 |
|------------|------|----------|
| 部分安卓机型 `vibrateShort` 无效 | 只有视觉反馈 | 调用前判断 `wx.vibrateShort` 存在，失败不抛错 |
| 部分安卓机型马达较弱，`light` 仍像"短嗡" | 与"不要通知感"的诉求有差距 | 平台上限，无法再细化；真机若不满意，降级为纯视觉（`hover-class` + 缩放） |
| 震动在提交中被重复触发 | 手感嘈杂 | 提交进行中跳过震动 |
| `hover-class` 与既有 `:active` 叠加导致颜色过深 | 观感不一致 | 两者使用同一档颜色 |
| 删页面漏改 `app.json` | 编译报错 / 白屏 | 一次改完，改后跑 `node --check` 与开发者工具编译 |
| 误删仍在用的 `getLearningStatus` | 「我的」「词单详情」报错 | 非目标写死；只删 `getNextWord` / `submitReview` |
| `#002` proposal 的「保留 reviewApi 三个方法」表述会失真 | 文档漂移 | 同一批改动里给 `#002` 补一行注记 |

**待确认问题**（未勾选 = 阻塞批准；得到答案后改成 `- [x]`，并在冒号后补结论）

- [x] **待确认** 震动的目的与强度？→ 用户答复：「本意是希望用户能通过触感明显感觉到自己按了某个选项，并不希望像收到消息一样震动」。结论：这是**触感确认**而非"提醒"，只能用**单次、极短的 `light` 级**反馈；**禁用** `vibrateLong`、禁用连续两次震动（这正是"收到消息"的手感）。
- [x] **待确认** 学习页（`pages/learn`）是否一并处理？→ 用户答复：「学习页已经不需要了，本轮顺便去掉」，**删除页面及专属封装**。

## 7. 决策记录

| 日期 | 决策 | 理由 | 被否决的备选 |
|------|------|------|-------------|
| 2026-10-28 | 用 `hover-class` 而不是只靠 `:active` | 小程序中 `hover-class` 触发更即时、跨机型一致 | 纯 `:active`（现状，真机延迟） |
| 2026-10-28 | 震动用 `wx.vibrateShort({ type: 'light' })` | 与项目内既有写法一致（`utils/fabDrag.js`） | `wx.vibrateLong`（过重） |
| 2026-10-28 | 震动只做「单次 short + light」，明确禁用长震与双震 | 用户要的是"按到了"的触感确认，不是通知提醒；消息级手感来自长震/双震 | `vibrateLong`、连震两次（更像通知，且打断复习节奏） |
| 2026-10-28 | 删除 learn 页与其两个专属封装，而不是给它补交互 | 零入口页面，改造无人可见；连同封装一起删才符合 `#002` 的判据 | 给 learn 页也加 hover + 震动（改完仍没人能看到） |
| 2026-10-28 | 删除范围并入 `#006` 而非新开 `#007` | 用户要求"本轮顺便去掉"；两者都只碰复习域，且 `#006` 尚未批准，扩范围成本最低 | 新开独立 change（多一轮审批，收益仅在文档更纯） |
| 2026-10-28 | 按下色 0.30 → 0.40（`scale(0.96)` 不变） | 用户反馈"再加深一点"；0.40 仍在同色系内，不会盖住下方浅灰文案 | 继续叠加 `scale` 或改文字颜色（会破坏四档色相的一致性） |
| 2026-10-28 | 空白区只加触感，不加底色/缩放 | 它是整块空白，变色会被误读成可输入区或按钮 | 也给空白区加 `hover-class` 变色 |

## 8. 验收摘要

> 详细规格见 `spec.md`。

- AC-01 按下任意评分按钮，按钮底色立即加深，抬起或移出后恢复
- AC-02 按下触发一次轻震动
- AC-03 不支持震动 / 关闭触感时静默跳过，不影响评分
- AC-04 提交中重复按下仍加深，但不重复提交、不重复震动
- AC-05 `app.json` 不再声明 `pages/learn/learn`，页面文件已删除
- AC-06 全仓库无指向 `/pages/learn/learn` 的引用
- AC-07 `reviewApi` 只剩 `getLearningStatus`
- AC-08 四条主链路走查无报错、无白屏
- AC-09 点「点击空白处显示答案」区域时，答案展示且轻震一次
