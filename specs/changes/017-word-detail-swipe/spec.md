## 新增需求

### R1 左右滑动切换单词

- **AC-01** 当用户从单词列表进入单词详情页，并在页面内容区**向左**滑动（横向位移 ≥ 60px，且横向位移 ≥
  纵向位移 ×1.5）时，系统应切换到该列表中的**下一个**单词，并展示其完整详情
  （单词、发音、释义、例句、收藏状态）。
- **AC-02** 当用户在同一页面**向右**滑动（判定条件同上，方向相反）时，系统应切换到列表中的**上一个**单词。
- **AC-03** 当当前单词是列表中的**第一个**单词且用户右滑时，系统应**不切换**，并提示「已经是第一个单词」。
- **AC-04** 当当前单词是列表中的**最后一个**单词且用户左滑时，系统应**不切换**，并提示「已经是最后一个单词」。
- **AC-05** 当进入详情页时**没有**携带所在列表的单词序列，或该序列只有 1 个单词时，系统应**不响应**左右滑动
  （不切换、不提示、不报错）。
- **AC-06** 当切换完成时，系统应：回到页面顶部、收起「更多」菜单与所有弹层、停止正在播放的音频、
  按「查词时折叠释义」配置重算释义展开状态、重新读取新单词的收藏状态。
- **AC-07** 如果切换时详情加载失败（网络失败 / 单词已删除），系统应**停留在切换前的单词**并保留其原有界面状态，
  同时给出可理解的失败提示，不得展示空白页或半截数据。
- **AC-08** 系统应**只**在切换判定成立时改变当前单词；纵向滚动、点击释义展开、播放音频、加入词单、收藏、
  更多菜单（重新学习 / 纠错 / 删除）的既有行为不得改变，横向位移不足或方向偏纵向时不得切换。

### R2 切换顺序与列表一致

- **AC-09** 系统应采用**列表页当前展示顺序**作为切换顺序（词单详情页：当前栏目〔未选/已选/全部〕的
  分组顺序 → 组内顺序 → 「未分组」在最后；分组内单词列表：该分组的单词顺序），
  且**不得**为切换单独发起网络请求获取相邻单词。
- **AC-10** 系统应为切换提供一次可感知的过渡：**卡片整块跟着手指横向移动**，松手后顺着方向滑出，
  新内容自另一侧滑入（见 AC-11 / AC-12）；请求尚未返回期间旧内容必须保持可见，不得整页空白。

### R3 跟手拖动与滑出滑入（2026-11-19 追加，用户要求「看着卡片往左移动/往右移动」）

- **AC-11** 当用户在单词详情页按住卡片横向拖动时，系统应让**整张卡片实时跟随手指横向位移**
  （位移量与手指一致），并随拖动距离增加而逐渐变淡；拖动超过卡片宽度 45% 后位移应带阻尼变缓，
  序列到头时阻尼更大（做出「拉不动」的手感）。
  判定为纵向滚动时卡片**不得**产生任何横向位移。
- **AC-12** 当用户松手时，系统应：位移达到阈值（≥60px，或 ≥30px 且速度 ≥0.6px/ms 的快速甩动）则
  让卡片顺着方向滑出、换内容后新卡片自另一侧滑入；未达阈值则**弹回原位**且不切换。
  滑出时应从卡片**当前跟手位置**继续滑走，不得先弹回中央再滑出。
  切换失败时卡片应滑回中央并保留原内容。

## 界面契约

| AC | 出现位置 | 形态 | 文案（逐字） | 用户动作 | 消失条件 |
|----|---------|------|-------------|---------|---------|
| AC-01 / AC-02 | 单词详情页内容区（单词卡片、释义区，含空白处） | **不新增元素**；整页内容区为滑动手势区 | — | 手指在内容区横向滑动 ≥60px 后抬起 | —（手势区常驻，不可见） |
| AC-03 | 页面底部居中的轻提示（系统 toast） | toast（`icon: none`），约 3 秒自动消失 | `已经是第一个单词` | 在第一个单词上右滑 | 约 3 秒后自动消失 |
| AC-04 | 同上 | 同上 | `已经是最后一个单词` | 在最后一个单词上左滑 | 约 3 秒后自动消失 |
| AC-05 | 无 | **不新增元素、不提示** | — | 滑动 | — |
| AC-06 | 页面内容区 | **不新增元素**；切换后自动回到顶部、收起弹层 | — | 触发切换 | — |
| AC-07 | 页面底部居中的轻提示（系统 toast）+ 仍显示原单词 | toast + 内容回到原位 | 请求层/详情页失败提示（如 `加载失败`，取接口 `message`） | 触发切换 | toast 约 3 秒消失；页面停留在原单词 |
| AC-10 | 页面内容区 | 不限 | — | 触发切换 | — |
| AC-11 | 整个单词卡片（含单词、释义、例句；**不含**底部「加入词单 / 收藏」栏） | **不新增元素**；卡片整体横向平移并随距离变淡，超出 45% 宽度后阻尼，序列到头时阻尼更大 | — | 按住卡片横向拖动（未松手） | 松手后进入 AC-12 的滑出或弹回 |
| AC-12 | 同上 | **不新增元素**；松手后卡片沿手指方向滑出（约 180ms），新卡片自另一侧滑入；未达阈值则弹回 | — | 松手 | 新卡片归位、透明度恢复 1 |

**界面契约附加说明**

1. **位置**：手势区覆盖详情页内容区（单词卡片 + 释义列表 + 页面空白），不覆盖底部固定操作栏的点击。
2. **形态**：本次**不新增任何常驻可见元素**（无箭头、无页码、无提示条）；交互反馈只有内容过渡与系统 toast。
3. **文案**：边界提示逐字为「已经是第一个单词」「已经是最后一个单词」，不得改成「到头了」之类。
4. **动作**：滑动本身不需要点任何按钮；滑动手势不替代任何既有按钮。
5. **消失条件**：toast 自动消失；过渡动画结束后内容复位；不产生任何需要用户关闭的浮层。

**不加东西（写死）**

| 场景 | 形态 |
|------|------|
| 有可切换的相邻单词 | **不新增元素**，靠内容过渡提示切换成功 |
| 没有列表上下文 / 序列只有 1 个单词 | **不新增元素、不提示** |
| 切换失败 | **不新增元素**，靠请求层 toast + 内容回到原单词 |

## 边界与异常

| 场景 | 预期行为 |
|------|----------|
| 序列只有 1 个单词（如只有 1 个词的分组） | 左右滑动均不响应、不提示（AC-05） |
| 从「分组管理」页（未分组截断列表）进入详情 | 无序列 → 不响应（AC-05，见 proposal 非目标） |
| 快速连续滑动 | 上一次滑出/装载未完成时忽略新的滑动，不并发装载多个单词 |
| 请求返回后的 180ms 过渡期间点击 | 内容已换成新单词（过渡只是视觉），点击作用在新单词上，不会误伤旧单词 |
| 接口失败 / 单词已删除 | 保留原单词与原界面状态，提示失败（AC-07） |
| 进入详情后被纠错页覆盖再返回 | 序列仍保存在页面内，滑动照常可用 |
| iOS 从屏幕最左边缘起滑 | 可能被系统「返回」手势接管（已知限制，不额外处理） |
| 未登录冷启动 | 详情加载本就会等 token；滑动判定不依赖登录状态，仅切换时会发起详情请求 |

## 数据契约

- 无新增/修改接口、无新增后端字段。
- 仅在页面间传递导航上下文：`{ ids: string[], currentId: string }`
  （`ids` 为列表当前展示顺序的单词 id，全程字符串，遵守 C-03）。
- 该上下文**只在内存中**（页面实例 `data`），不落缓存、不入 storage。
