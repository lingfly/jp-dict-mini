## 1. 问题（Why）

**现在发生了什么？**
从词单详情页（`pages/wordlist-detail`）或分组内单词列表（`pages/wordlist-group-words`）点开一个单词后，
进入 `pages/word-detail`。想连续看列表里的下一个词，必须：返回列表 → 找到刚才那一行 → 点下一个词。
单词详情页本身没有任何「上一个 / 下一个」的入口。

**谁受影响？** 在词单里按顺序浏览、核对释义的用户（整理词单、抽查释义、连续看同一分组的词）。

**有多疼？** 每看一个词就多两次操作（返回 + 再点），且返回后列表可能已经滚动走位；一条 20 个词的列表要点
20 次「返回 + 点行」。属于高频但单次代价小的痛点。

**证据**：代码事实 —— `pages/word-detail/word-detail.js` 只有 `onLoad` 里的单个 `wordId`，没有任何相邻单词的概念；
列表页三处跳转（`wordlist-detail.js:601`、`wordlist-group-words.js:180`、`wordlist-group.js:442`）都只传一个 `wordId`。

## 2. 目标（What）

一句话：让**在词单里连续浏览单词的用户**，在单词详情页**左右滑动**就能切到列表里的**上一个 / 下一个单词**，
从而**不返回列表也能连续看词**。

## 3. 非目标（Out of Scope）★

- 本次**不做**首页查词结果（`pages/home`）的左右滑动切换。该页是搜索结果 + AI 结果混合流，没有稳定顺序，
  本次不碰。
- 本次**不做**复习页（`pages/review-list`）的上一个/下一个卡片（那是 `TODO.md` 第 7 条，属于复习调度能力）。
- 本次**不做**「分组管理页」（`pages/wordlist-group`）未分组单词列表的滑动上下文：该页只展示「未分组」且默认截断 8 条，
  序列不完整，作为上下文会误导用户。从该页进入详情时，左右滑动**不响应**（与本次新增的降级行为一致）。
- 本次**不做**任何新的常驻界面元素：不加「上一个 / 下一个」按钮、不加页码/序号指示器、不加滑动提示箭头。
- 本次**不做**手势之外的切换入口（不加「上一个 / 下一个」按钮，不做键盘/语音控制）。
- 本次**不做**预加载相邻单词详情、不做详情页缓存、不改任何接口。
- 本次**不改**单词详情页的既有行为：释义折叠、音频播放、加入词单、收藏、更多菜单（重新学习 / 纠错 / 删除）、
  文字选中、页面纵向滚动全部保持原样。
- 本次**不改**列表页的展示顺序、分组折叠状态与勾选逻辑。

## 4. 用户与场景

| 角色 | 场景 | 现在怎么做 | 期望怎么做 |
|------|------|-----------|-----------|
| 整理词单的用户 | 打开词单 → 单词列表 → 点开一个词，想接着看下一个 | 返回列表再点下一行 | 在详情页左滑，直接到下一个词 |
| 抽查释义的用户 | 连续看同一分组里的若干词 | 反复返回 / 进入 | 左滑下一页、右滑回上一页，列表顺序不变 |
| 在词单列表首个/末个单词 | 想再往前/往后滑 | — | 提示「已经是第一个单词」/「已经是最后一个单词」，不跳转、不白屏 |

## 6. 风险与未知

| 风险 / 未知 | 影响 | 处理方式 |
|------------|------|----------|
| 横向滑动与纵向滚动冲突 | 用户想上下滚动却切了词 | 判定同时要求「横向位移 ≥60px」且「横向位移 ≥ 纵向位移 ×1.5」且「按下到抬起 ≤900ms」，纵向滚动时 `dy` 占优不会误触 |
| iOS 左边缘返回手势抢占右滑 | 从屏幕最左侧起滑可能触发系统返回 | 接受（系统手势优先）；从页面中部起滑可正常切上一个词，写入「已知限制」 |
| 长文本选中（`selectable`） | 横向拖动可能被识别为文本选择 | 文本选择由长按触发，普通横向拖动不受影响；如真机发现异常，记录到 `TODO.md` 再评估 |
| 慢网下切换后长时间无内容 | 用户以为卡死 | 旧内容先向滑动方向偏移并淡出 18%，新数据回来后再从另一侧淡入；失败则回到原位并保留原单词 |
| 列表页数据在详情页停留期间变化（如别处删词） | 序列里含已删单词 | 切换失败走「保留原单词 + 提示」，不静默跳号；序列只在进入详情时取一次（不新增请求） |
| 详情页被「纠错页」叠加后返回 | 事件通道仍在，序列不丢 | 序列保存在页面 `data` 中，与页面实例同生命周期；返回后滑动仍可用 |
| 无法在本次会话做真机验证 | 不能声称「验收通过」 | 状态保持 `approved`，只勾实现类任务；真机/模拟器验收由用户完成后才置 `verified` |

## 7. 决策记录

| 日期 | 决策 | 理由 | 被否决的备选 |
|------|------|------|-------------|
| 2026-11-18 | 由**列表页**把「当前栏目的单词 id 序列」交给详情页，交接方式是 `utils/wordNav.js` 的「令牌 + 内存暂存」 | 序列就是用户眼前的顺序（栏目 + 分组 + 排序都由列表页决定），详情页不需要新接口、不会与列表顺序不一致；令牌天然按「谁打开了我」隔离，页面栈里多个详情页实例也不会串 | ① 详情页自己调 `/api/wordlist/all-content` 重算序列（多一次请求、可能和列表页排序参数不一致）② 把 id 数组拼进 `url`（长度上限、多词单会超限）③ 塞 `globalData` 单槽（多实例互相覆盖）④ `eventChannel.emit`（`navigateTo` 的 success 与新页 `onLoad` 谁先谁后不确定，emit 早于监听就静默丢失，见 design §1） |
| 2026-11-18 | 手势判定放在 `touchend`，用位移 + 时间 + 方向三个条件 | 不需要跟手动画就能避免与竖向滚动冲突；实现小、无误触成本 | 跟手拖动（需要 `catchtouchmove`，会破坏纵向滚动） |
| 2026-11-18 | **先请求、后切换**：数据回来前旧单词内容保持可见，成功后播放「滑入 + 淡入」过渡 | 慢网下不出现整页空白；失败也可原样退回 | ① 先推走旧内容再请求（慢网会长时间停在推走的状态，看着像空白）② 直接切到「加载中...」（页面闪白） |
| 2026-11-19 | 改为**跟手拖动**：`touchmove` 实时移动整张卡片，松手后从当前位置滑出、新卡片滑入；横向判定一开始就预取相邻两个词 | 用户原话「看着卡片往左移动/往右移动」——原来只有松手后一次性位移，看不出在「翻卡片」；预取让滑出→滑入没有空窗 | ① 保留原来的「松手才动」过渡（用户明确否掉）② 用 `<swiper>` 组件整块翻页（会失去释义区内部的点击/滚动，且需重排整个页面） |
| 2026-11-18 | 不新增任何常驻 UI | 用户只要求「滑动切换」；加指示器是产品决策，未获得明确要求 | 顶部加 `3/20` 页码、底部加左右箭头 |

## 8. 验收摘要

- AC-01 从列表页进入详情页后，左滑切到列表中的下一个单词。
- AC-02 右滑切回上一个单词。
- AC-03 第一个再右滑 / 最后一个再左滑，只提示「已经是第一个单词」/「已经是最后一个单词」，不跳转。
- AC-05 没有列表上下文（或序列只有 1 个单词）时，左右滑动不产生任何切换与提示。
- AC-06 切换后：回顶部、收起菜单与弹层、停止音频、释义展开态按配置重置、收藏状态取新单词。
- AC-07 切换失败时保留切换前的单词与原状态，并给出可理解的提示。
- AC-09 切换顺序与列表当前栏目一致，且不为切换额外请求列表。

### 11.1b 追加：跟手拖动（2026-11-19）

- 用户原话：「**能不能做出看着卡片往左移动/往右移动的效果**」——原先只有松手后一次整块位移，
  看不出「卡片在翻」，据此改为跟手拖动。
- 实现：`bindtouchmove` 实时 `transform: translate3d` + 透明度；轴判定（锁 'x'/'y'）；
  45% 宽度后阻尼、到头阻尼更大；松手按「远 / 快 / 够远且不慢」三条任一成立则从当前位置滑出，
  换内容后新卡片自另一侧滑入；未达标弹回；横向判定一开始就预取相邻两词避免空窗。
- 开发者工具实测（`.jointest/v017-drag.js` **9/9**）：
  拖 40px → `dragX=-40`、透明度 0.85；拖 120px → `dragX=-120`、透明度 0.55；
  `boundingClientRect` 实测卡片 `left 33 → -104`（真的在跟手移动，不是只改数据）；
  松手后切到下一个且归位（dragX=0/dragging=false/opacity=1）；
  只拖 18px 松手 → 弹回不切换；纵向拖动 → 卡片 `dx=0` 且不切词。
- 纯逻辑（`.jointest/verify-017.js`）**31/31**：含阻尼曲线、到头阻尼、甩动无 touchmove 也能切。
- 截图：`.jointest/shots/017-drag-mid.png`（拖到一半）、`017-after-drag.png`（松手归位后）。
