## 1. 问题（Why）

**现在发生了什么？** `#005` 交付的学习统计页有三处与预期不符：

1. 进入页面时「今天」整列铺了一层淡绿底（`rgba(91,140,125,0.10)`，高度等于整个绘图区 720rpx + 标签区），看起来像一根很高的淡色柱，比真实数据柱更抢眼。
2. 首次进入时「今天」不在正中：`BAR_WIDTH` 写死 82rpx，而图表可视宽度随设备浮动（375px 屏正好 574rpx，414px 屏约 586rpx），列宽与可视宽度不整除，今天居中后两侧各露出小半列，看起来"没对齐"。
3. 详情卡里「学习时长」另起一行独占右侧，与上方 7 项数值网格错位；同一张卡里出现两套对齐方式。

**谁受影响？** 所有查看学习统计的用户。

**有多疼？** 每次进入页面都能看到，属于"一眼可见"的观感问题。

**证据**：用户 2026-10-29 的反馈（原文见 §9）；代码 `review-forecast.wxss` 的 `.bar-col-active`、`review-forecast.js` 的 `BAR_WIDTH` 与 `scrollToToday`。

## 2. 目标（What）

> 一句话：让图表回归"数据说话"——不画与数值无关的底色、一屏正好是「前 3 天 + 今天 + 后 3 天」、详情卡 8 项数值一套网格对齐。

## 3. 非目标（Out of Scope）★

- 本次**不做**：不改纵轴上限策略（`#005` 的全期统一上限仍保留）。
- 本次**不做**：不改接口、不改数据解析、不改柱段颜色与图例。
- 本次**不做**：不改一屏天数（仍是 7 天），也不加时间范围切换器。
- 明确**不改**的既有行为：点击某列仍会切换详情卡内容；切换图表仍回到今天；下拉刷新、四态展示（加载/空/失败/重试）不变。

## 4. 用户与场景

| 角色 | 场景 | 现在怎么做 | 期望怎么做 |
|------|------|-----------|-----------|
| 用户 | 进入学习统计 | 今天整列被淡绿底罩住 | 只有数据柱，无整列底色 |
| 用户 | 首次进入 / 切换图表 | 今天偏左或偏右，两侧露半列 | 今天正中，左侧 3 天、右侧 3 天完整可见 |
| 用户 | 查看某日详情 | 学习时长独占一行 | 学习时长在「待学」右边，第 8 格 |

## 5. 成功标准

| 类型 | 标准 | 怎么观测 |
|------|------|----------|
| 视觉 | 图区内不存在任何与数值无关的整列底色 | 开发者工具 WXML 面板：`.bar-col` 无 `bar-col-active` 类 |
| 视觉 | 首屏与切图后，今天左右各 3 列完整、无半列露出 | 视口截图数格子 |
| 视觉 | 详情卡第二行为「新学 / 复习 / 待学 / 学习时长」 | 打开详情卡核对 |
| 功能 | 点柱换详情、切图回今天、下拉刷新均不变 | Console 无新增报错 |

## 6. 风险与未知

| 风险 / 未知 | 影响 | 处理方式 |
|------------|------|----------|
| 去掉选中底色后，点击某列缺少视觉反馈 | 用户不确定点中哪一天 | 详情卡的日期会立即变化，作为反馈；本次不新增指示元素（要加另开 change） |
| 列宽改为按可视宽度反推（可能带小数） | 相邻列可能出现亚像素缝 | 保留 1 位小数（误差 < 0.05px）；`.bar-area` 的左边框会掩盖接缝 |
| 首帧按 82rpx / 360rpx 渲染、随后按实测值重排 | 极短一帧的尺寸跳变 | 与 `#005` 相同的一次 `setData` 重排；图表本就随数据到达才出现 |
| 一屏布局依赖 `height:100vh` + flex 链（页面 → 卡片 → 图表区） | 某层 `min-height` 漏写会让图表不缩，退化成仍可上下滚 | 每一层都写了 `min-height: 0`；极端小屏兜底 `MIN_PLOT_HEIGHT = 200rpx`（宁可略超一屏也不压扁柱子） |

**待确认问题**：无（用户已把三条要求写全）。

## 7. 决策记录

| 日期 | 决策 | 理由 | 被否决的备选 |
|------|------|------|-------------|
| 2026-10-29 | 直接移除整列高亮，不换其它选中指示 | 用户要求"去掉那个很高的淡色柱"；新增指示元素属于新需求 | 只保留柱顶一小段色条 / 只改标签颜色 |
| 2026-10-29 | 列宽由可视宽度 ÷ 7 反推，滚动目标 = 今天左侧第 3 列贴左边缘 | 比 `今天中心 − 视口一半` 更稳：列宽与视口天然整除，不依赖设备宽度假设 | 保留 82rpx、按 `round(视口/82)` 决定一屏天数（会出现 6 天或 8 天） |
| 2026-10-29 | 学习时长并入 4 列网格第 8 格，值字号降为 24rpx | 25% 列宽放不下 32rpx 的「12 分 30 秒」 | 单独一行（用户已否决）/ 改时长文案格式（`AC-24` 固定了文案） |
| 2026-10-29 | **改为与其余 7 项完全同款字（32rpx / 600 / `#303133`），只保留 `nowrap`** | 用户问「字体样式和其他几个一致吗」——不一致就是 bug，观感优先于极端长文案 | 24rpx 降档（上一版做法）/ 用 `scale` 缩放 |
| 2026-10-29 | 一屏不滚动：页面 `height:100vh` 纵向 flex，图表卡 `flex:1` 吃掉剩余高度 | 用户要求「上下方向在一屏展示」；比写死更小的高度更稳，且柱高自动变大 | 把 720rpx 改成一个更小的固定值（小屏仍会溢出） |
| 2026-10-29 | 柱段高度由 rpx 改为**百分比**，绘图区高度由 JS 量剩余空间后以 rpx 下发 | 百分比让柱高与绘图区高度解耦；但 `.chart` 的 `height:100%` 要穿过 `scroll-view` 内部结构，不可靠，故外层高度仍用 rpx 显式写死 | 全用 `height:100%` 链（`scroll-view` 内部包装层高度不确定，风险是柱子全不显示） |

## 8. 验收摘要

- AC-01：柱区不存在整列底色；选中某列的反馈只体现为详情卡内容变化。
- AC-02：图表可视宽度被 7 列等分；首屏与切图后，今天左侧 3 列、右侧 3 列完整可见且无半列露出。
- AC-03：详情卡数值网格为 4 列 2 行：简单/认识/模糊/忘记 + 新学/复习/待学/学习时长。
- AC-04：`#005` 的 AC-09 / AC-19 / AC-20 / AC-21 / AC-24 口径按本提案替换，其余 AC 不变。
- AC-05：学习时长的标签与数值沿用其余 7 项同一套字号 / 字重 / 颜色（22rpx 灰标签 + 32rpx 600 深灰值），不额外降档。
- AC-06：整页纵向一屏装完（切换项 + 图表卡 + 详情卡），默认不需要上下滑动；绘图区高度按剩余空间自适应，纵轴刻度与绘图区上下沿对齐。

> 本变更覆盖 `#005` 的下列条款：AC-09 / AC-19（居中口径改为「7 列等分 + 今天居中」）、AC-20（取消整列高亮）、AC-21 / AC-24（学习时长移到网格第 8 格）、AC-11 / AC-17（绘图区不再固定 720rpx，改由一屏剩余高度决定）。
